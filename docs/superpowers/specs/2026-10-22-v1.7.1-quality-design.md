# Humming 1.7.1: tests, quality gates, measured numbers, refreshed homepage (design)

Date: 22 October 2026. Branch `upgrade/v1.7.1` from `main` (`6ac587d`).

## Intent

1.7.0 shipped features. 1.7.1 adds no user-facing features. It proves what the app does: more unit tests on the logic
behind dictation, a real emulator run that sets up the keyboard and types with it, static-analysis gates that stop
new problems, startup and model-load numbers measured on an emulator, and a README and website that show screenshots
from that run instead of hand-made captures from 1.3/1.4.

The requirements are the frozen task's Definition of Done. The owner opted out of design questions ("carry on through
routine work without asking"), so every choice below is **the builder's call** unless the task says otherwise.

## Goals

1. **Unit tests** for non-UI logic: text post-processing, settings (`Prefs`), model management (`ModelStore`
   download, verify, unpack, delete) and language switching (the subtype cycle behind the language key). JUnit 4 on
   the JVM, Robolectric where Android types are needed. A JaCoCo report measures line coverage of `com.humming.keyboard`
   before and after, from CI.
2. **Emulator smoke test** on GitHub Actions (`reactivecircus/android-emulator-runner`): enable Humming as the
   keyboard, open Android's keyboard settings and Humming's own settings, type with Humming's keys into the
   "Try out your setup" field, check the text arrived. Screenshots are workflow artifacts.
3. **Static analysis gates**: ktlint and detekt (command-line releases pinned by SHA-256, no Gradle plugin) and
   Android lint (`:app:lintDebug`), each with a baseline that holds only the issues that exist today; gitleaks;
   Dependabot for Gradle and GitHub Actions; CodeQL for Java/Kotlin.
4. **Measured numbers** from the emulator run, labelled with the system image and date: cold start of the
   release-like (`benchmark`, R8) build with `am start -W`, and load time of the Fast voice model through the app's
   own `SherpaEngine`. Anything not measurable is written as INFERRED.
5. **README and website** refreshed with the emulator screenshots, badges for the new gates, install from Releases,
   privacy, architecture, links. The live site returns HTTP 200.
6. **Release plumbing**: version 1.7.1 everywhere (Android versionCode 1701, desktop, core, iOS build 1701, as for
   1.7.0, because `assemble_release.py` refuses a tag that differs from the desktop version), CHANGELOG
   `[1.7.1] - 2026-10-22`, SKILLS_USED.md, TASKS.md, HANDOFF.md.

## Non-goals

- New keyboard or dictation features, UI redesign of the keyboard itself.
- Fixing every pre-existing lint/ktlint/detekt finding in the FlorisBoard base (they go in baselines; new code must be clean).
- Macrobenchmark or Perfetto profiling (the `:benchmark` module stays as it is).
- Pinning third-party actions to SHAs (still a HANDOFF item).

## Anti-goals (a failure even if it "works")

- A number in the README or site that did not come from a committed CI output.
- A gate that silently passes: a missing baseline must fail the job, not create itself and pass.
- A change to the applicationId, package names, signing key, or the stored preference/history formats.
- A test that downloads a model or touches the network in the normal unit-test run.

## Constraints

- No Gradle, cargo, Xcode or Docker on the development machine: every Kotlin change is unverified until CI runs.
- Push only through `push.sh` (branch pushes only; no tags). Tagging `v1.7.1`, which makes `release.yml` attach the
  signed APK to the GitHub Release, happens after review and merge.
- Workflows on `main` trigger on `main` pushes and pull requests only; they must also run on `upgrade/**` pushes so
  this branch's head is checked.

## Builder's calls

- **Baselines are generated by CI, then committed.** The first push runs each tool with no baseline; the job writes the
  baseline as an artifact and fails. The baseline is downloaded, read, and committed; later runs fail only on new issues.
- **ktlint + detekt CLIs** instead of Gradle plugins: detekt 1.23.8's Gradle plugin is not built for Kotlin 2.2 / Gradle
  9, and the CLIs only parse sources, so they cannot break the build.
- **Smoke test drives the real UI with UiAutomator** (keys carry `contentDescription`s since 1.7.0), and screenshots are
  `screencap` files in `/data/local/tmp/humming`, pulled after the run.
- **Model-load test** is an instrumented test that runs only when the workflow passes `-e humming.modelBench true`; it
  downloads the Fast model through `ModelStore.download` (the app's own path, SHA-256 checked) and times three loads.
- **Language switching**: the next/previous-language rule in `SubtypeManager` moves into a pure `SubtypeCycle` with
  tests. One behaviour change, test-first: if the active language is no longer in the list, switching goes to the first
  language in the list instead of `Subtype.DEFAULT` (which may not be in the list).
- **Coverage** via AGP's built-in JaCoCo (`enableUnitTestCoverage`), summarised by `scripts/coverage_summary.py`.
- **Architecture section** gets a module/data-flow diagram generated from the code (archify), linked from README.
